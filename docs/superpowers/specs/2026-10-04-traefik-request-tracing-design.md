# Traefik request logging and tracing to Elasticsearch — design

Date: 2026-10-04 (amended same day after planning-stage investigation)
Status: approved; amendment awaiting review

## Goal

Record every request routed by homeauto's Traefik in Elasticsearch, and give each
request a key that links the Traefik record to what the backend app did with it.

Serves three uses:

- **Debugging** — "this request to X failed": see Traefik's record and X's logs at that moment.
- **Security / audit** — a complete record of who hit what, from where, with what result.
- **End-to-end tracing** — an exact shared key in every hop, for apps that can carry it.

## Scope

- In: homeauto Traefik (`traefik/docker-compose.yaml`), the 61 Traefik-routed services on
  homeauto, and repairing container log ingestion on homeauto (Logstash GELF, Filebeat).
- Out: deepcore, octoprint, adsb and other hosts; custom images or sidecars to instrument
  apps that lack native OpenTelemetry support; a durable on-disk queue for ELK outages;
  the 90-day, 77 GB `metrics-apm.app.traefik-default` stream (noted, not changed).

## Decisions

| Topic | Decision |
|---|---|
| Correlation key | W3C trace ID (`trace.id`), generated by Traefik's existing OTLP tracing |
| Transport | Traefik `accesslog.otlp` → existing `apm-server:8200` → ES APM data streams |
| Coverage | Every routed request, no status/duration filters |
| Retention | 30 days for access logs and traces (ILM) |
| Sensitive data | Header allowlist; redact auth headers; strip secret query parameters before indexing |
| Backend correlation | Tier 1 exact key where config allows; Tier 2 container + time window for all |
| ELK config location | In the repo, inline in `elk-stack/docker-compose.yaml` via `configs: content:` |

## Facts established during planning (2026-10-04)

- **Trace ID on access logs — confirmed in source.** Traefik v3.7.13
  `pkg/middlewares/accesslog/logger.go:220-227` sets `trace_id`/`span_id` (and deprecated
  `TraceId`/`SpanId`) on every access-log entry from the request span, and passes the
  request context to the OTLP log exporter (`:386`). Phase 0 still verifies end to end.
- **OTLP access logs need `--experimental.otlpLogs=true`** (`pkg/config/static/static_config.go:497`).
- **Query parameters are all-or-nothing in Traefik** (`fields.queryparameters.defaultmode`),
  so selective redaction stays in ES.
- **APM data streams are ILM-managed** (`next_generation_managed_by: ILM`).
  `traces-apm.traces-default_policy` rolls over at 30 d and deletes 10 d after rollover.
  The templates call `traces-apm@custom` / `logs-apm.app@custom` pipelines and include
  `traces-apm@custom` / `logs-apm.app@custom` component templates; none exist yet.
- **Volume:** ~1.24 M Traefik requests/day; `traces-apm-default` grows ~1.7 GB/day.
  ES disk (shared NFS for es01/es02): 294.7 GB total, 128.6 GB free.
- **Container logs are not reaching ES at all:**
  - GELF → Logstash → `logs-generic-default`: every event rejected with 400
    `object mapping for [host] tried to parse field [host] as object` (GELF `host` is a string).
  - Filebeat's container input reads `/var/lib/docker/containers/*.log` (wrong glob) and the
    container has no mount of `/var/lib/docker/containers`.
  - Logstash and Filebeat configs live only on homeauto under `/docker/…`.
- **Compose remote deploy:** with `DOCKER_HOST=ssh://`, bind-mount and `configs: file:`
  sources resolve on the remote host (Compose v2.38.2 `pkg/compose/create.go:1043-1060`).
  `configs: content:` is copied via the Docker API (`pkg/compose/secrets.go:71-99`), so it
  is the way to keep config in the repo.

## Architecture

```
client ──► Traefik (homeauto)
            │  creates trace + span, injects `traceparent` upstream
            │  ├─ OTLP traces  ──────────┐   (existing)
            │  └─ OTLP access logs ──────┤   new: accesslog.otlp, dualOutput
            ▼                            ▼
        backend app              apm-server:8200 ──► ES
         │ Tier 1: continues trace,                    traces-apm-default     (spans)
         │   sends spans to apm-server ──────────────► logs-apm.app.traefik-default
         │                                                (access log, trace.id)
         │ Tier 2: stdout ─► GELF ─► Logstash ─┐
         │                ─► json-file ─► Filebeat ─┴─► logs-docker-default
         ▼                                            (container.name + @timestamp)
```

## Components

### 1. Traefik access-log export

Changes to the `command:` list in `traefik/docker-compose.yaml`:

- `--experimental.otlpLogs=true`
- `--accesslog.format=json`, `--accesslog.bufferingsize=100`, `--accesslog.dualoutput=true`
- `--accesslog.otlp.http.endpoint=http://172.24.32.13:8200/v1/logs`,
  `--accesslog.otlp.serviceName=traefik`
- Header fields, `--accesslog.fields.headers.defaultmode=drop`:

| Mode | Headers |
|---|---|
| keep | `User-Agent`, `Referer`, `X-Forwarded-For`, `X-Real-Ip`, `Content-Type`, `Traceparent`, `X-Request-Id` |
| redact | `Authorization`, `Cookie`, `Set-Cookie`, `X-Api-Key`, `X-Ha-Access` |

Standard fields kept (default `keep`), query parameters kept (redacted in ES).

### 2. ES pipelines and retention (`elk-stack/apm-custom/`)

JSON bodies plus an idempotent `apply.sh` (PUTs to `http://172.24.32.13:9200`) and a
`test.sh` that exercises the pipelines with `_ingest/pipeline/_simulate`.

- **`traces-apm@custom` and `logs-apm.app@custom` pipelines** both call a shared
  **`redact-secrets`** pipeline that replaces the values of `apikey`, `api_key`, `token`,
  `access_token`, `auth`, `password`, `signature` (case-insensitive) with `REDACTED` in:
  `url.original`, `url.full`, `url.query`, `message`, and the access-log request-path
  attribute (exact field name fixed in Phase 0).
- **`on_failure`:** remove those fields and set `error.message`, so a document that failed
  redaction is never indexed with its secret intact.
- **Retention:** ILM policy `apm-30d` (hot rollover `max_age: 1d` / `max_primary_shard_size: 50gb`;
  delete `min_age: 30d`). The `traces-apm@custom` and `logs-apm.app@custom` component
  templates set `index.lifecycle.name: apm-30d` and `index.lifecycle.prefer_ilm: true`.
  `apply.sh` also sets the policy on existing backing indices and rolls over both streams.
- `logs-apm.app@custom` additionally runs the enrich processor (component 3).

### 3. Service → container map (Tier 2 join)

- `elk-stack/apm-custom/service-map.sh` reads `docker ps` labels on homeauto (via
  `DOCKER_HOST=ssh://bagpuss@172.24.32.13`) and writes a `traefik-service-map` index:
  Traefik service name (e.g. `kibana01@docker`) → `container.name`.
- Enrich policy `traefik-service-map` on that index; `logs-apm.app@custom` adds
  `container.name` to each access-log document.
- Rerun after stack changes (script re-executes the enrich policy). Unmapped requests have
  no `container.name` and fall back to `ServiceURL` IP:port.

### 4. Container log ingestion repair

All ELK config moves into the repo, inline in `elk-stack/docker-compose.yaml` using
top-level `configs:` with `content:`; host bind mounts of `/docker/logstash/…` and
`/docker/filebeat/…` are removed. `$` in config text is escaped as `$$`.

- **Logstash:** `logstash.yml`, `pipelines.yml` and all five pipelines (`syslog`, `gelf`,
  `fluentd`, `syslog-esphome`, `syslog-opnsense`) copied verbatim from homeauto, with one
  change to `gelf`: before output, rename `host` → `[host][name]`, `container_name` →
  `[container][name]`, `container_id` → `[container][id]`, `image_name` →
  `[container][image][name]`; output to data stream dataset `docker`
  (`logs-docker-default`).
- **Filebeat:** existing inputs kept; container input fixed to
  `/var/lib/docker/containers/*/*-json.log`, `add_docker_metadata` added; container events
  written to `logs-docker-default`. Compose mounts `/var/lib/docker/containers:ro` and
  `/var/run/docker.sock:ro`.
- `logs-docker-default` uses the built-in `logs-*-*` template and `logs` ILM policy
  (30 d rollover, delete 30 d after).

### 5. Backend correlation

- **Tier 2 (all routed services):** Kibana saved search over `logs-docker-default`
  filtering `container.name` and `@timestamp` within ±2 s of the request.
- **Tier 1 (config/env only, verified 2026-10-04):**

| App | Settings | Continues incoming `traceparent` |
|---|---|---|
| Grafana 13.2.3 | `GF_TRACING_OPENTELEMETRY_OTLP_ADDRESS=172.24.32.13:8200` (gRPC), `GF_TRACING_OPENTELEMETRY_OTLP_PROPAGATION=w3c`, `GF_TRACING_OPENTELEMETRY_SAMPLER_TYPE=const`, `GF_TRACING_OPENTELEMETRY_SAMPLER_PARAM=1` | yes |
| Kibana 9.5.4 | `ELASTIC_APM_ACTIVE=true`, `ELASTIC_APM_CONTEXT_PROPAGATION_ONLY=false`, `ELASTIC_APM_SERVER_URL=http://apm-server:8200` | yes |
| Nautobot 3.2.6 | `OTEL_PYTHON_DJANGO_INSTRUMENT=True`, `OTEL_TRACES_EXPORTER=otlp`, `OTEL_EXPORTER_OTLP_ENDPOINT=http://172.24.32.13:8200`, `OTEL_SERVICE_NAME=nautobot` | yes (documented) |
| Open WebUI v0.11.4 | `ENABLE_OTEL=true`, `ENABLE_OTEL_TRACES=true`, `OTEL_EXPORTER_OTLP_ENDPOINT=http://172.24.32.13:8200`, `OTEL_OTLP_SPAN_EXPORTER=http`, `OTEL_SERVICE_NAME=open-webui` | yes |
| Homebox 0.26.2 | `HBOX_OTEL_ENABLED=true`, `HBOX_OTEL_ENDPOINT=172.24.32.13:8200`, `HBOX_OTEL_PROTOCOL=grpc`, `HBOX_OTEL_INSECURE=true` | yes |
| Karakeep | `OTEL_TRACING_ENABLED=true`, `OTEL_EXPORTER_OTLP_TRACES_ENDPOINT=http://172.24.32.13:8200/v1/traces`, `OTEL_SERVICE_NAME=karakeep` | API routes only |
| Immich v3.2.4 | `IMMICH_TELEMETRY_INCLUDE=all`, `OTEL_TRACES_EXPORTER=otlp`, `OTEL_EXPORTER_OTLP_ENDPOINT=http://172.24.32.13:8200` | likely; undocumented — verify |

  apm-server accepts OTLP gRPC and HTTP on port 8200. Selenium also qualifies but is not
  user-facing; skipped. Apps fronted by their own nginx/Apache with mountable config
  (nginx_core, openspeedtest, phpMyAdmin, FreshRSS, Smokeping) can log `$http_traceparent`;
  deferred until Tier 1 is proven. Everything else stays Tier 2.

### 6. Kibana

- Data view `logs-apm.app.traefik-*` with a saved Discover search for the access log.
- Saved search for Tier 2 over `logs-docker-default`.
- Trace lookup through the built-in APM UI.

## Failure handling

- **apm-server or ES down:** Traefik's OTLP exporter drops data and never blocks requests.
  `docker logs traefik` (json-file, 10m × 3) is the short local fallback. Gaps accepted.
- **Pipeline error:** URL fields dropped, document tagged (component 2).
- **Stale service map:** missing `container.name`; fall back to `ServiceURL`.
- **Logstash cutover breaks a pipeline:** Logstash logs the failing pipeline; previous
  configs remain on homeauto under `/docker/logstash/` for comparison. Brief ingestion gaps
  are acceptable (home lab).
- **Disk:** ~52 GB of traces plus access and container logs at 30 days against 128.6 GB
  free. If headroom drops below 40 GB, reduce trace span detail first.

## Testing

1. `docker compose -f <file> config --quiet` on every changed compose file.
2. `elk-stack/apm-custom/test.sh` — `_simulate` cases for redaction, case-insensitivity,
   untouched non-secret params, `on_failure`, and enrich.
3. Live: `curl -H 'Authorization: Bearer secret' 'https://<svc>.viewpoint.house/x?apikey=SECRET&ok=1'`,
   then in ES: `trace.id` present and matches `traces-apm-default`; `Authorization`
   redacted; `apikey=REDACTED`; `ok=1` intact; `User-Agent` kept; unlisted header absent;
   traces doc redacted too; `container.name` enriched.
4. `GET <stream>/_ilm/explain` shows `apm-30d` on the write index of both APM streams.
5. `logs-docker-default` receives docs from both a GELF container (radarr) and a json-file
   container (traefik) within 5 minutes of deploy; Logstash log has no 400 rejections.
6. Tier 1: one request to Grafana shows Traefik and Grafana spans under one trace.

## Rollout

Each phase is a PR. Claude does not run `up.sh` or `docker compose up` unless asked;
ES API changes via `apply.sh` are run with the user's go-ahead.

0. **Spike** — Traefik OTLP access logs only. Confirm `trace.id` in ES; record the OTLP
   attribute names for request path and headers.
1. **ES redaction and retention** — pipelines, ILM, component templates.
2. **Traefik header allowlist.**
3. **Container log ingestion repair** — ELK configs inline, GELF fix, Filebeat fix.
4. **Service map, enrich, Kibana saved searches.**
5. **Tier 1 apps.**

## Known risks

- ES security is disabled (`xpack.security.enabled=false`); anything indexed is readable
  from the LAN. Redaction limits the damage but is not access control.
- Turning container logs back on surfaces existing noise (a container on homeauto has
  restarted 19,452 times; fr24feed logs `Too many open files` every 5 s) and adds volume.
