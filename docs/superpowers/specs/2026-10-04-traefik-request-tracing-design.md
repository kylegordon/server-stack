# Traefik request logging and tracing to Elasticsearch — design

Date: 2026-10-04
Status: approved in brainstorming, awaiting spec review

## Goal

Record every request routed by homeauto's Traefik in Elasticsearch, and give each
request a key that links the Traefik record to what the backend app did with it.

Serves three uses:

- **Debugging** — "this request to X failed": see Traefik's record and X's logs at that moment.
- **Security / audit** — a complete record of who hit what, from where, with what result.
- **End-to-end tracing** — an exact shared key in every hop, for apps that can carry it.

## Scope

- In: homeauto Traefik (`traefik/docker-compose.yaml`) and the 61 Traefik-routed services on homeauto.
- Out: deepcore, octoprint, adsb and other hosts; custom images or sidecars to instrument
  apps that lack native OpenTelemetry support; a durable on-disk queue for ELK outages.

## Decisions

| Topic | Decision |
|---|---|
| Correlation key | W3C trace ID (`trace.id`), generated by Traefik's existing OTLP tracing |
| Transport | Traefik `accesslog.otlp` → existing `apm-server:8200` → ES APM data streams |
| Coverage | Every routed request, no status/duration filters |
| Retention | 30 days, access logs and traces |
| Sensitive data | Header allowlist; redact auth headers; strip secret query parameters before indexing |
| Backend correlation | Tier 1 exact key where config allows; Tier 2 container + time window for all |

## Architecture

```
client ──► Traefik (homeauto)
            │  creates trace + span, injects `traceparent` upstream
            │  ├─ OTLP traces  ──────────┐   (existing)
            │  └─ OTLP access logs ──────┤   new: accesslog.otlp, dualOutput
            ▼                            ▼
        backend app              apm-server:8200 ──► ES
         │ Tier 1: continues trace,                    traces-apm-*     (spans)
         │   sends spans/logs to apm-server ─────────► logs-apm.app-*   (access log, trace.id)
         │ Tier 2: stdout ─► GELF/Filebeat ─► Logstash ─► existing logs indices
         ▼                                            (container.name + @timestamp)
```

Logstash, Filebeat, GELF and all backends are unchanged in the first phases.

## Components

### 1. Traefik access-log export

Changes to the `command:` list in `traefik/docker-compose.yaml`:

- `--accesslog.format=json`, `--accesslog.bufferingsize=<n>`
- `--accesslog.otlp=true`, HTTP exporter to `http://172.24.32.13:8200` (same endpoint
  family as the existing `--tracing.otlp.http.endpoint`), with `dualOutput` so stdout
  still carries the JSON log.
- Header fields, default `drop`:

| Mode | Headers |
|---|---|
| keep | `User-Agent`, `Referer`, `X-Forwarded-For`, `X-Real-Ip`, `Content-Type`, `Traceparent`, `X-Request-Id` |
| redact | `Authorization`, `Cookie`, `Set-Cookie`, `X-Api-Key`, `X-Ha-Access` |

Standard fields are kept: start time, `Duration`, `OriginDuration`, method, host, path,
protocol, `ClientHost`, `OriginStatus`, `DownstreamStatus`, sizes, `RouterName`,
`ServiceName`, `ServiceURL`, TLS version/cipher, `RetryAttempts`.

Exact flag names for the OTLP access-log exporter and the resulting OTLP attribute names
are confirmed in Phase 0 against Traefik v3.7 before the rest is written.

### 2. ES ingest pipeline and retention (`elk-stack/apm-custom/`)

New directory holding JSON plus an idempotent `apply.sh` that PUTs them to `es01:9200`.
Applied by hand, like `elk-stack/curator/`.

- **`logs-apm.app@custom` pipeline:** replaces the values of `apikey`, `api_key`, `token`,
  `access_token`, `auth`, `password`, `signature` (case-insensitive) with `REDACTED` in
  request path / URL fields. Runs the enrich processor (component 3).
- **Same redaction on the traces data stream's `@custom` pipeline**, because Traefik spans
  carry `url.full` / `http.target`. Redaction on one stream without the other is pointless.
- **`on_failure`:** remove the URL fields and tag `error.message`, so a document that failed
  redaction is never indexed with its secret intact.
- **Retention:** `@custom` component templates set 30-day retention on the APM logs and
  traces data streams. ES 9.x standalone APM uses data-stream lifecycle
  (`data_retention: 30d`); if Phase 0 shows ILM instead, an equivalent ILM policy is used.
  Confirm Curator jobs do not touch `logs-apm*` / `traces-apm*`.

### 3. Service → container map (Tier 2 join)

- A script reads `docker ps` labels on homeauto and writes a `traefik-service-map` index
  (Traefik service name, e.g. `kibana01@docker` → container name).
- An ES enrich policy on that index; the `logs-apm.app@custom` pipeline adds
  `container.name` to each access-log document.
- Rerun after stack changes; idempotent. Unmapped requests have no `container.name` and
  fall back to `ServiceURL` IP:port.

### 4. Backend correlation

- **Prerequisite:** every routed container's stdout reaches ES. About 24 compose files use
  GELF today; Filebeat's config lives on the host (`/docker/filebeat/filebeat.yml`).
  Phase 0 checks coverage. Gaps are closed by having Filebeat collect all containers on
  homeauto, not by editing compose files one by one.
- **Tier 2 (all routed services):** Kibana saved search filtering container logs on
  `container.name` and `@timestamp` within ±2 s of the request's start and duration.
- **Tier 1 (opportunistic):** apps that can join the trace through config or env vars only
  (e.g. `OTEL_EXPORTER_OTLP_ENDPOINT=http://172.24.32.13:8200` or an app-specific setting).
  Grafana (native OTLP tracing) is the first. The implementation plan contains a verified
  audit table of the 61 services; this spec does not assert which others qualify. Apps
  fronted by their own nginx/Caddy may add `$http_traceparent` to their log format where
  that config is exposed.

### 5. Kibana

- Saved Discover view / dashboard for the access log: by router, status, client IP, latency.
- Saved search for Tier 2 "container logs for this request".
- Trace lookup through the built-in APM UI.

## Failure handling

- **apm-server or ES down:** Traefik's OTLP exporter drops data and never blocks requests.
  `docker logs traefik` (json-file, 10m × 3) is the short local fallback. Audit gaps during
  ELK outages are accepted.
- **Pipeline error:** URL fields dropped, document tagged (see component 2).
- **Stale service map:** missing `container.name`; fall back to `ServiceURL`.
- **apm-server load:** watched via its existing metrics in Kibana during rollout. Traefik's
  tracing samples 100% by default; if storage is a problem, reduce span detail before
  access-log completeness.

## Testing

1. `docker compose -f <file> config --quiet` on every changed compose file.
2. `curl -H 'Authorization: Bearer secret' 'https://<svc>.viewpoint.house/x?apikey=SECRET&ok=1'`,
   then in ES:
   - access-log document has `trace.id`, matching a span in `traces-apm-*`;
   - `Authorization` redacted; `apikey=REDACTED`; `ok=1` intact; `User-Agent` kept;
     an unlisted header absent;
   - the matching traces document has the same `apikey` redaction;
   - `container.name` enriched.
3. `GET _data_stream/logs-apm.app*` and `traces-apm*` show 30-day retention.
4. Tier 1: one request to Grafana shows Traefik and Grafana spans in one trace.

## Rollout

Each phase is its own branch and PR. Claude does not run `up.sh` or deploy; the user deploys.

0. **Spike — go/no-go.** Enable OTLP access-log export only. Confirm `trace.id` is on the
   access-log record and matches the Traefik span; record OTLP attribute names, the APM
   data stream names, retention mechanism, and Filebeat container coverage.
   **If `trace.id` is absent:** stop and revise to fall back to a Traefik request-ID plugin
   generating `X-Request-Id`, logged and forwarded alongside the OTLP pipeline.
1. **Redaction and retention** — apply pipelines and templates before widening header capture.
2. **Header allowlist** — full Traefik flags.
3. **Service map and enrich** — Tier 2 and the Kibana saved searches.
4. **Tier 1 apps** — from the verified audit table, one PR per batch.

## Known risks

- The `trace.id`-on-access-log behaviour is inferred from OTel log semantics, not stated in
  Traefik's docs. Phase 0 exists to prove it.
- ES security is disabled (`xpack.security.enabled=false`); anything indexed is readable
  from the LAN. Redaction limits the damage but is not access control.
- Volume of 100%-sampled traces plus access logs on NFS-backed ES storage is unmeasured.
